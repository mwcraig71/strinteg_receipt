# Strinteg Receipt Sorter

Employees sign in, upload or email their receipts, and each one is read automatically by Claude: merchant, date, every line item, totals, and the Strinteg expense type and vendor for each line. The app checks each read against the receipt's own arithmetic and flags anything to look at. For a date range, the employee submits their checked receipts, which locks them and produces a ZIP to attach to the ERP expense report:

- `Receipts_<name>_<from>_to_<to>.xlsx` — expense lines (tax spread across items), totals by expense type, a receipt list
- `..._all-receipts.pdf` — every receipt, one per page, with a header line
- `receipts/` — each receipt as its own file, named `01_2026-11-01_Home-Depot_100.61.jpg`

Each person sees only their own receipts.

## How a receipt is read

1. **Intake.** Uploads (PDF, JPEG, PNG, HEIC) and emailed attachments are stored on the server. Scanned PDFs are split into page images with `pdftoppm` at 220 dpi; each page is its own receipt unless the user turns that off. Forwarded e-receipts with no attachment are read from the email text.
2. **Clean-up.** The page image is turned upright, cropped if the user drew a crop, trimmed of blank margins, and contrast-stretched so faded thermal print turns dark and paper turns white.
3. **Strips.** Claude scales any image above about 1.15 megapixels down to that size. A full-page scan or long receipt is sent as a small overview plus overlapping full-resolution horizontal strips, so small print stays readable.
4. **Read.** One Claude API call with the images, the expense-type list, the vendor list and the Strinteg rules. The fixed instructions are prompt-cached, so repeat reads pay about a tenth for them. Claude answers through a tool schema, so the result is always structured.
5. **Checks.** Plain code, not AI: line items vs. total, subtotal + tax + tip, date sanity, missing expense types, project number on direct costs, phone over $100, vendor on the list.

| Button | Model | Rough cost per receipt |
|---|---|---|
| Automatic read | `claude-sonnet-5-5` (`MODEL_STANDARD`) | 3–8¢ |
| Re-read carefully | `claude-opus-5-5` (`MODEL_CAREFUL`) | 6–16¢ |
| Re-sort for this purpose (text only) | `claude-haiku-5-5` (`MODEL_QUICK`) | under 0.1¢ |

The app records the Claude cost of each receipt; it shows under the line items.

## Deploy on Render

1. **Push this folder to a GitHub repository.**
2. **Clerk.** In the Clerk dashboard create an application (email sign-in is enough; restrict sign-ups to `@strinteg.com` under *Restrictions → Allowlist* if you want only staff). Copy the publishable key and secret key.
3. **Anthropic.** Create an API key in the Claude Console for the company account.
4. **Render.** *New → Blueprint*, pick the repository. It creates the web service (Docker, with a 10 GB disk for receipt files) and a Postgres database. Fill in `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` and `ANTHROPIC_API_KEY` when asked. Leave `INBOUND_ADDRESS` blank for now.
5. **Clerk domain.** In Clerk, add the Render URL (e.g. `https://strinteg-receipts.onrender.com`) as an allowed origin / production domain.
6. Sign in and upload a receipt.

### Email-in (Postmark)

1. Create a Postmark account and a server. Under *Default Inbound Stream → Settings*, copy the inbound address (`xxxx@inbound.postmarkapp.com`).
2. Set the webhook URL to
   `https://postmark:<INBOUND_WEBHOOK_PASSWORD>@<your-render-host>/inbound/postmark`
   (the password is generated by Render; find it under the service's *Environment*). Attachments are included in the webhook by default.
3. Set `INBOUND_ADDRESS` on Render to the Postmark address and redeploy.
4. Each user's personal address appears under **Email receipts in**: `xxxx+<their code>@inbound.postmarkapp.com`. Mail sent to the plain address from a user's sign-in email also reaches them.

Later, with IT adding an MX record for a subdomain like `receipts.strinteg.com`, Postmark can receive at `receipts@receipts.strinteg.com` instead; change `INBOUND_ADDRESS` and nothing else.

## Run locally

```bash
npm install
npm start            # http://localhost:3000
```

With no `CLERK_SECRET_KEY` and `NODE_ENV` not `production`, the app signs you in as a local test user. With no `ANTHROPIC_API_KEY` it returns a canned read so you can try the whole flow. Data goes to an embedded Postgres in `.data/`. Install `poppler-utils` for PDF support.

## Settings

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string (Render fills this) |
| `STORAGE_DIR` | Where receipt files are kept (`/var/data/files` on Render) |
| `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY` | Sign-in |
| `ANTHROPIC_API_KEY` | Claude API |
| `MODEL_STANDARD`, `MODEL_CAREFUL`, `MODEL_QUICK` | Models for each kind of read |
| `READ_CONCURRENCY` | Receipts read at the same time (default 2) |
| `INBOUND_ADDRESS`, `INBOUND_WEBHOOK_PASSWORD` | Postmark email-in |
| `MAX_UPLOAD_MB` | Largest file per upload (default 25) |

The expense types and vendors are in `data/expense_list.txt` and `data/vendor_list.txt`, in the same tab-separated layout copied from the ERP. Replace them and redeploy to update.
